# Memory-related and span types

.NET includes a number of interrelated types that represent a contiguous, strongly typed region of arbitrary memory. These types are designed to allow the creation of algorithms that *avoid copying memory or allocating on the managed heap* more than necessary. Creating them (either via `Slice`, `AsSpan()`, a collection expression, or their constructors) does not involve duplicating the underlying buffers: only the relevant references and offsets, which represent the "view" of the wrapped memory, are updated. In high-performance code, spans are often used to avoid allocating strings unnecessarily.

The types include:

- [`System.Span`](https://learn.microsoft.com/dotnet/api/system.span), a type that's used to access a contiguous region of memory. A [`Span`](https://learn.microsoft.com/dotnet/api/system.span) instance can be backed by an array of type `T`, a buffer allocated with [stackalloc](https://learn.microsoft.com/dotnet/csharp/language-reference/operators/stackalloc), or a pointer to unmanaged memory. Because it has to be allocated on the stack, it has a number of restrictions. For example, a field in a class cannot be of type [`Span`](https://learn.microsoft.com/dotnet/api/system.span), nor can span be used in asynchronous operations.

- [`System.ReadOnlySpan`](https://learn.microsoft.com/dotnet/api/system.readonlyspan), an immutable version of the [`Span`](https://learn.microsoft.com/dotnet/api/system.span) structure. Instances can be also backed by a [`String`](https://learn.microsoft.com/dotnet/api/system.string).

- [`System.Memory`](https://learn.microsoft.com/dotnet/api/system.memory), a wrapper over a contiguous region of memory. A [`Memory`](https://learn.microsoft.com/dotnet/api/system.memory) instance can be backed by an array of type `T` or a memory manager. As it can be stored on the managed heap, [`Memory`](https://learn.microsoft.com/dotnet/api/system.memory) has none of the limitations of [`Span`](https://learn.microsoft.com/dotnet/api/system.span).

- [`System.ReadOnlyMemory`](https://learn.microsoft.com/dotnet/api/system.readonlymemory), an immutable version of the [`Memory`](https://learn.microsoft.com/dotnet/api/system.memory) structure. Instances can also be backed by a [`String`](https://learn.microsoft.com/dotnet/api/system.string).

- [`System.Buffers.MemoryPool`](https://learn.microsoft.com/dotnet/api/system.buffers.memorypool), which allocates strongly typed blocks of memory from a memory pool to an owner. [`IMemoryOwner`](https://learn.microsoft.com/dotnet/api/system.buffers.imemoryowner) instances can be rented from the pool by calling [`System.Buffers.MemoryPool`1.Rent`](https://learn.microsoft.com/dotnet/api/system.buffers.memorypool-1.rent) and released back to the pool by calling [`System.Buffers.MemoryPool`1.Dispose`](https://learn.microsoft.com/dotnet/api/system.buffers.memorypool-1.dispose).

- [`System.Buffers.IMemoryOwner`](https://learn.microsoft.com/dotnet/api/system.buffers.imemoryowner), which represents the owner of a block of memory and controls its lifetime management.

- [`MemoryManager`](https://learn.microsoft.com/dotnet/api/system.buffers.memorymanager), an abstract base class that can be used to replace the implementation of [`Memory`](https://learn.microsoft.com/dotnet/api/system.memory) so that [`Memory`](https://learn.microsoft.com/dotnet/api/system.memory) can be backed by additional types, such as safe handles. [`MemoryManager`](https://learn.microsoft.com/dotnet/api/system.buffers.memorymanager) is intended for advanced scenarios.

- [`ArraySegment`](https://learn.microsoft.com/dotnet/api/system.arraysegment), a wrapper for a particular number of array elements starting at a particular index.

- [`System.MemoryExtensions`](https://learn.microsoft.com/dotnet/api/system.memoryextensions), a collection of extension methods for converting strings, arrays, and array segments to [`Memory`](https://learn.microsoft.com/dotnet/api/system.memory) blocks.

For more information, see the [`System.Buffers`](https://learn.microsoft.com/dotnet/api/system.buffers) namespace.

## Working with memory and span <a class="anchor" href="#working-with-memory-and-span" id="working-with-memory-and-span">#</a>
Because the memory-related and span-related types are typically used to store data in a processing pipeline, it's important that you follow a set of best practices when using [`Span`](https://learn.microsoft.com/dotnet/api/system.span), [`Memory`](https://learn.microsoft.com/dotnet/api/system.memory), and related types. These best practices are documented in [Memory\<T> and Span\<T> usage guidelines](../ch12/11.html).
