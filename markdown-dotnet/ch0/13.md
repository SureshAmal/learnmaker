# dotnet format

**This article applies to:** ✔️ .NET 6 SDK and later versions

## Name <a class="anchor" href="#name" id="name">#</a>
`dotnet format` - Formats code to match `editorconfig` settings.

## Synopsis <a class="anchor" href="#synopsis" id="synopsis">#</a>
```dotnetcli
dotnet format [<PROJECT | SOLUTION>]
  [--binarylog <BINARY-LOG-PATH>] [--diagnostics <DIAGNOSTICS>]
  [--exclude <EXCLUDE>] [--exclude-diagnostics <EXCLUDE-DIAGNOSTICS>]
  [--include <INCLUDE>] [--include-generated]
  [--no-restore] [--report <REPORT-PATH>] [--severity <LEVEL>]
  [-v|--verbosity <LEVEL>] [--verify-no-changes] [--version]

dotnet format -h|--help
```

## Description <a class="anchor" href="#description" id="description">#</a>
`dotnet format` is a code formatter that applies style preferences and static analysis recommendations to a project or solution. Preferences will be read from an *.editorconfig* file, if present, otherwise a default set of preferences will be used. For more information, see the [EditorConfig documentation](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/configuration-files#editorconfig).

## Arguments <a class="anchor" href="#arguments" id="arguments">#</a>
`PROJECT | SOLUTION`

The MSBuild project or solution to run code formatting on. If a project or solution file is not specified, MSBuild searches the current working directory for a file that has a file extension that ends in *proj* or *sln*, and uses that file.

> **\1**
>
> dotnet format may restore, compile, and run analyzers from the specified project or solution. Only invoke the tool against trusted code.

## Options <a class="anchor" href="#options" id="options">#</a>
None of the options below are required for the `dotnet format` command to succeed, but you can use them to further customize what is formatted and by which rules.

- **`--binarylog <BINARY-LOG-PATH>`**

  Logs all project or solution load information to a binary log file.

- **`--diagnostics <DIAGNOSTICS>`**

  A space-separated list of diagnostic IDs to use as a filter when fixing code style or third-party issues. Default value is whichever IDs are listed in the *.editorconfig* file. For a list of built-in analyzer rule IDs that you can specify, see the [list of IDs for code-analysis style rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/index).

- **`--exclude <EXCLUDE>`**

  A space-separated list of relative file or folder paths to exclude from formatting. The default is none.

- **`--exclude-diagnostics <EXCLUDE-DIAGNOSTICS>`**

  A space-separated list of diagnostic IDs to exclude when fixing code style or third-party issues. Default value is none. For a list of built-in analyzer rule IDs that you can specify, see the [list of IDs for code-analysis style rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/index).

- **`--include <INCLUDE>`**

  A space-separated list of relative file or folder paths to include in formatting. The default is all files in the solution or project.

- **`--include-generated`**

  Formats files generated by the SDK.

- **`--no-restore`**

  Doesn't execute an implicit restore before formatting. Default is to do implicit restore.

- **`--report <REPORT-PATH>`**

  Produces a JSON report in the directory specified by `<REPORT_PATH>`.

- **`--severity <LEVEL>`**

  The minimum severity of diagnostics to fix. Allowed values are `info`, `warn`, and `error`. The default value is `warn`.

- **`--verify-no-changes`**

  Verifies that no formatting changes would be performed. Terminates with a non zero exit code if any files would have been formatted.

- **`--version`**

  Displays version information.

- **`-v|--verbosity <LEVEL>`**

Sets the verbosity level of the command. Allowed values are `q[uiet]`, `m[inimal]`, `n[ormal]`, `d[etailed]`, and `diag[nostic]`. For more information, see [`LoggerVerbosity`](https://learn.microsoft.com/dotnet/api/microsoft.build.framework.loggerverbosity).

- **`-?|-h|--help`**

Prints out a description of how to use the command.

## Subcommands <a class="anchor" href="#subcommands" id="subcommands">#</a>
### Whitespace <a class="anchor" href="#whitespace" id="whitespace">#</a>
`dotnet format whitespace` - Formats code to match `editorconfig` settings for whitespace.

#### Description <a class="anchor" href="#description" id="description">#</a>
The `dotnet format whitespace` subcommand only runs formatting rules associated with whitespace formatting. For a complete list of possible formatting options that you can specify in your *.editorconfig* file, see the [C# formatting options](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/csharp-formatting-options).

#### Options <a class="anchor" href="#options" id="options">#</a>
- **`--folder`**

  Treat the `<PROJECT | SOLUTION>` argument as a path to a simple folder of code files.

### Style <a class="anchor" href="#style" id="style">#</a>
`dotnet format style` - Formats code to match EditorConfig settings for code style.

#### Description <a class="anchor" href="#description" id="description">#</a>
The `dotnet format style` subcommand only runs formatting rules associated with code style formatting. For a complete list of formatting options that you can specify in your `editorconfig` file, see [Code style rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/index).

#### Options <a class="anchor" href="#options" id="options">#</a>
- **`--diagnostics <DIAGNOSTICS>`**

  A space-separated list of diagnostic IDs to use as a filter when fixing code style issues. Default value is whichever IDs are listed in the *.editorconfig* file. For a list of built-in code style analyzer rule IDs that you can specify, see the [list of IDs for code-analysis style rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/style-rules/index).

- **`--severity <LEVEL>`**

  The minimum severity of diagnostics to fix. Allowed values are `info`, `warn`, and `error`. The default value is `warn`

### Analyzers <a class="anchor" href="#analyzers" id="analyzers">#</a>
`dotnet format analyzers` - Formats code to match `editorconfig` settings for analyzers (excluding code style rules).

#### Description <a class="anchor" href="#description" id="description">#</a>
The `dotnet format analyzers` subcommand only runs formatting rules associated with analyzers. For a list of analyzer rules that you can specify in your `editorconfig` file, see [Quality rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/index).

##### Options <a class="anchor" href="#options" id="options">#</a>
- **`--diagnostics <DIAGNOSTICS>`**

  A space-separated list of diagnostic IDs to use as a filter when fixing non code style issues. Default value is whichever IDs are listed in the *.editorconfig* file. For a list of built-in analyzer rule IDs that you can specify, see the [list of IDs for quality rules](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/index). For third-party analyzers refer to their documentation.

- **`--severity <LEVEL>`**

  The minimum severity of diagnostics to fix. Allowed values are `info`, `warn`, and `error`. The default value is `warn`.

## Examples <a class="anchor" href="#examples" id="examples">#</a>
- Format all code in the solution:

  ```dotnetcli
dotnet format ./solution.sln
```

- Clean up all code in the application project:

  ```dotnetcli
dotnet format ./src/application.csproj
```

- Verify that all code is correctly formatted:

  ```dotnetcli
dotnet format --verify-no-changes
```

- Clean up all code in the *src* and *tests* directory but not in *src/submodule-a*:

  ```dotnetcli
dotnet format --include ./src/ ./tests/ --exclude ./src/submodule-a/
```

- Fix a specific **code style** issue:  

  ```dotnetcli
dotnet format style --diagnostics IDE0005 --severity info
```

- Fix all **code style** issues that have severity `info`, `warning` or `error`:

  ```dotnetcli
dotnet format style --severity info
```

- Fix a specific (non code style) analyzer issue:

  ```dotnetcli
dotnet format analyzers --diagnostics CA1831 --severity warn
```

- Fix all non code style issues that have severity `info`, `warning` or `error`:  

  ```dotnetcli
dotnet format analyzers --severity info
```
